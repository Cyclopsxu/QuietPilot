# 三轮真实中文输入并行测试

前提：手机机主参与；不要把自动脚本输入当作人在持续拼音输入。严格模式默认不放行能力不足设备；Mate 40 Pro 仅在机主已明确选择兼容实验模式时运行。不要为录像切换系统隔离配置。

1. 构建并部署最新 shell/控制端，先确认无未结束任务。按 `docs/DEMO.md` 启动录制；先单独验证两路 scrcpy 对焦点、控件和截图的影响。保留版本、任务 ID 与开始时间。F8 采集需使用现场已有工具；本仓库没有定义 F8 快捷键，不能声称本脚本代替了它。
2. 主屏打开华为备忘录的专用测试笔记或微信文件传输助手。保持中文拼音候选词栏出现，持续输入并穿插滚动至少 60 秒。记录人观察到的候选词消失、输入打断、转屏与主动切换的时间。测试文字不含个人信息。
3. 后台依次执行三个不同的需要文字输入的任务，例如：备忘录创建独立测试笔记、高德搜索公共地点、高德规划两个公共地点间路线。主屏与后台不能是同一 App；同 App 优先暂停属于预期保护，另测并记录。短任务不足 60 秒不得用结束后的空闲时间凑数。
4. `DisturbanceMonitor` 约每 500ms 读取窗口、输入和输入法，归档 `disturbance.focusSamples` 含 epoch 时间、窗口焦点、IME 客户端/目标、剪贴板摘要、步骤。最慢采样、跳过 tick 与截断单独报告，不能把缺失记为 0。任务轨迹记录目标与实际可确认的注入路径，其余路径显示 unrecorded 并查动作日志。
5. 等 `finalized=true`，用 `getTask` 导出任务 JSON（不写出凭据，去掉 evidenceBase64），并分别保存两路录像、任务日志、人工记录。JSON 中加入的人工注释必须明确是人工记录，不能修改原始观测。
6. `node scripts/isolation-report.mjs round1.json round2.json round3.json > report.md`。报告列四项事件次数及最近动作；发生时间关联不等于因果。焦点/IME 非主屏按一次连续区间计一次，未知采样单列；剪贴板仅保留摘要，变化也可能来自用户。
7. 对非 0 事件结合动作日志、输入路径、两路录像定位；修复后使用新任务 ID 重跑三轮，保留失败轮。上传前按 `docs/evidence/README.md` 脱敏。三轮四项为 0、覆盖均≥60秒、候选词和视频核验完成才可写完整验收通过；否则明确缺口和实际影响。
